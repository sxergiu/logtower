# Logtower 0.3.0

A long log could only be read squeezed into its table row. This release adds an inspector that shows one log at a time in full, and lets you step through the logs in the current filter with the arrow keys. The title screen can also check for an update when you ask, instead of only at launch and once a day.

If you run 0.2.0 or 0.2.1, the title screen shows `v0.3.0 available` with an **Update** button. Installing it by hand works too. This release does not change the database.

## A long log could not be read in full (#32)

Click a log's message in Log View to open it in the inspector. The header and filter bar stay on top.

- **The detail card** shows the time and date in large type, the project and task badges, edit and delete, and the full message with its line breaks kept.
- **The list on the left** holds every log in the current filter. The inspected log is highlighted and kept in view, and clicking a row opens it.
- **‹ › or ← →** step through the logs in the table's order. The position shows as `3 / 12`. **Esc** or the back arrow returns to the table.

How it behaves:

- **Changing the filter**, from the filter bar or by clicking a badge, jumps to the newest log of the new set. If the set is empty, it shows "No logs found :(" with the back button.
- **Deleting a log** moves on to the next one, or to the previous one if it was the last. The inspector returns to the table when no logs are left.
- **While you edit**, the arrow keys and Esc do nothing in the inspector. Esc in the edit box cancels the edit only.
- **The project or task badge is hidden when you are already filtering by it**, the same way the table hides those columns.

## The title screen only checked for updates on its own schedule (#31)

Logtower checked for a new release at launch and then once a day, so a copy left running in the tray could not look for one when you wanted it to. A **check for updates** link now sits next to the version on the title screen. Clicking it shows "Checking for updates…" and then one of these:

- **Up to date**, with a "check again" link.
- **Couldn't check for updates**, with a "try again" link, for example when you are offline.
- The existing `vX available` and **Update** flow, when there is a newer version.

The checks at launch and once a day still show nothing unless there is an update, so the title screen doesn't flash a status every time Logtower starts.

## Known, and not fixed here

- **You can only browse the logs the current filter loaded.** There is no search and no date range.
- **The bulk Delete button is only on the table**, not in the inspector.
- **No update has been installed through the updater yet.** It has found 0.2.1 but has never downloaded and installed one, so updating to 0.3.0 may be its first full run. If the update fails, download the installer from this release page.
- **Not checked before release:** the release build of this version was not launched by hand. Both features were tested in the running development build, and CI builds and tests it on macOS, Linux and Windows.
- **Still true from 0.2.1:**
  - when Logtower fails to start on Windows, it shows nothing;
  - Esc does not close quick log while one of its dropdowns has focus;
  - on GNOME without the AppIndicator extension, there is no tray icon;
  - the installers are not code-signed, so macOS and Windows warn on first run;
  - the hotkey does not work on Wayland.
