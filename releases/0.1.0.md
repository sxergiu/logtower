# Logtower 0.1.0

Fixes for the things a v0.0.1-alpha user ran into: edits that reported a failure, log times shown in UTC, a crash when picking an empty project, and a second copy of the app when it was launched again. It is also the first release with installers for Intel Macs and Linux, built by CI for every platform.

Upgrading from v0.0.1-alpha keeps your projects, tasks and logs: install 0.1.0 over it. The database side of that is covered by a test (see #15 below).

## Editing a log said it failed, even though it had saved (#18)

On every database created by v0.0.1-alpha, editing a log showed an error and the log view did not refresh. The edit **was** saved, and no log was lost or changed by this. Re-reading after the save queried a `logs.project_id` column that the schema no longer has, and failed with `no such column: project_id`. Reproduced against a copy of a real `logs.db`. The query now reads the project through the log's task, like every other log query, and returns every row (12 of 12 on that copy).

## Every log time was shown in UTC (#19)

Logs are stored in UTC, and the log view printed that time as it was stored. In Romania every log appeared 2 hours early in winter and 3 in summer, and a log written just after local midnight appeared under the previous day. Times are now shown in your computer's time zone. Nothing changes in storage. For example, `2026-07-01 22:30:00` UTC now shows as `2026-07-02 01:30:00` in Bucharest.

## Picking a project with no tasks crashed the app (#16)

Choosing a project with no tasks clears the active task, and clearing it crashed the backend: a log line unwrapped the empty value before checking it. It no longer crashes.

## Launching Logtower again started a second, half-working copy (#21)

Closing the window leaves Logtower in the tray, so launching it again is the natural way to get the window back. That started a second copy, which added a second tray icon, could not register `Ctrl+Space`, and wrote to the same database as the first. Launching it again now brings the running window forward, and the second launch exits before it touches the hotkey, the tray or the database.

## A hotkey that failed to register was never mentioned (#20)

If another app already held `Ctrl+Space`, registering it failed silently and the dashboard still said "Press Ctrl+Space". The dashboard now names the shortcut that could not be registered and says another app may be using it.

## Schema changes never reached existing databases (#15)

Tables were created with "create if it doesn't exist", so a change to a table only ever applied to fresh installs. The schema is now applied as numbered migrations, tracked in the database's `user_version`. Your existing v0.0.1-alpha database adopts the first migration as it is, with its rows intact (covered by a test that runs it on a pre-migration database).

**A new install now starts empty.** Release builds used to seed sample projects and tasks. Only development builds do now, so you create your first project yourself.

## A database that failed to open still opened the app (#16)

If the database failed to initialize, the error was only printed, and the window opened anyway, accepting logs it could not save. Logtower now stops at startup instead.

## Installers for every platform, and the right tray icon (#22)

v0.0.1-alpha had an Apple Silicon `.dmg` and a Windows `.msi`, both built by hand. Publishing this release builds and attaches:

| Platform | Files |
|---|---|
| macOS, Apple Silicon | `Logtower_0.1.0_aarch64.dmg` |
| macOS, Intel | `Logtower_0.1.0_x64.dmg` |
| Linux | `.deb`, `.rpm`, `.AppImage` |
| Windows | `.msi`, `-setup.exe` |

Adding the Linux build also fixed an icon. On macOS and Linux, the tray icon and the Linux window icon came from a fallback that was Tauri's own logo. They are now the Logtower tower. Windows and the macOS app icon were already right.

## Known, and not fixed here

- **Nothing is signed.** On macOS, if it says the app is damaged, move it to Applications and run:
  ```bash
  xattr -dr com.apple.quarantine /Applications/Logtower.app
  ```
  On Windows, SmartScreen warns on first run. Choose **More info → Run anyway**.
- **The hotkey does not work on Wayland.** The global-shortcut library only supports X11 on Linux.
- **`Ctrl+Space` can be taken without a warning.** On macOS it is also "Select previous input source", and on Windows it switches the Chinese IME. Those take the key without refusing the registration, so the warning from #20 probably does not appear. If the hotkey does nothing, check those settings. A configurable hotkey is not in this release.
- **If startup fails, a release build exits without a message.** The error from #16 only reaches the console, which release builds do not have.
- The quick-log window does not show the hotkey warning. Only the dashboard does.
